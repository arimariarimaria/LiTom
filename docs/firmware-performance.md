# LiTom 軽量化と通信・安定性の更新提案

調査日: 2026-10-08。ログ収集は保留。今回の軽量版では依存モジュールの固定コミットを維持し、診断削除と表示処理の設定変更だけを行います。

## 今回反映する軽量化

- フリーズ診断のCコード、Kconfig項目、診断用ビルド定義、専用ワークフローを削除。
- 左右とも `ZMK_USB_LOGGING=n`、`ZMK_RTT_LOGGING=n`、`LOG=n`、`THREAD_ANALYZER=n`。StudioのUSB/BLE設定編集は維持。
- OLED表示用タイマーを10msから30msへ変更し、表示専用スレッドの優先度を5から6へ変更。左のBLEキー通知は4、親機のBLE HID通知は既定値5なので、表示より優先される。
- 既存の左OLED一括描画・連続入力時の再描画抑制は維持。

これは表示用タイマーの起動回数を減らす変更で、キースキャンやHIDレポートを30ms間隔にする変更ではありません。表示の追従は少し遅くなります。CPU使用率・入力遅延・無線品質の実測値はありません。

より強い軽量化はアニメーション停止、さらにOLED停止の順で検討できます。過去に左OLED停止時の改善報告があるため、表示は有力な負荷削減対象です。ただし親機全体のフリーズの原因とは確定していません。

## 推奨する次の更新

### 1. Zephyrの省電力時メモリ破損修正を試験する

現在固定している `7c6b4cc486ecb41a68d9c2b1def2bb3178fbb826` の後に、省電力移行でデバイス記録領域が確保されず、隣接するタイマー情報を書き壊す問題の修正があります。候補は同じDYA用系列の `63363d92c475ad203b35e9047cef7ecd8706a6fc` です。

[現在との差分](https://github.com/cormoran/zephyr/compare/7c6b4cc486ecb41a68d9c2b1def2bb3178fbb826...63363d92c475ad203b35e9047cef7ecd8706a6fc) は2ファイル、4コミット（マージを含む）です。[省電力修正](https://github.com/cormoran/zephyr/commit/dd75091e6cfe0b8be7853d191206884aa16daf82) はスリープ移行の安全性に関わります。もう1件はLS0xx表示用SPIロック修正で、LiTomのSSD1306 OLEDとは異なります。

省電力修正はBLE通信そのものの修正ではありません。今回の設定でスリープ処理が実行されるか確認したうえで、別の試験ビルドで採用し、USB/BLE入力・アイドル復帰・電源再投入・設定保存を確認することを推奨します。USB給電中の停止も報告されているため、今回のフリーズをこの不具合だけで説明できるとは限りません。軽量版にはまだ取り込んでいません。

### 2. BLE通信だけが不安定な場合に接続互換設定を比較する

現在のZMKには `ZMK_BLE_EXPERIMENTAL_CONN` があり、2M PHYを無効にする互換設定が含まれます。[定義](https://github.com/cormoran/zmk/blob/e5c9b6915b56801193e359dd9bad4a167ce0d1b8/app/Kconfig) のとおり実験的な設定です。表示も止まるフリーズが残る段階で、これを確定修正とは扱いません。

試す場合は左右を揃えた別ビルドにし、PCのBluetooth接続と左右間の接続を分けて比較します。右をUSB接続していても、左から右はBLEです。過去に左右間の省電力待ちを0にしても改善しなかったため、同じ変更は繰り返しません。送信出力やバッファ容量の一律増加も、根拠なく行いません。

### 3. PMW3610ドライバー更新は別途互換性を確認する

上流候補 `44b4a76b74d293a93cec4ccb7e04cb8d29c10f93` にはCPI/軸設定、スリープ時処理、移動量管理の変更があります。[差分](https://github.com/badjeff/zmk-pmw3610-driver/compare/e970029b42f33613ca8f05baf311dc733cd5a390...44b4a76b74d293a93cec4ccb7e04cb8d29c10f93) は現在の固定版と分岐しており、単純な後継ではありません。先に600 CPI・軸方向・Studio設定変更・スリープ復帰の互換性を確認する必要があります。左右全キーが重い症状への最優先策にはしません。

## 更新を急がないもの

調査時点でDYAの `main+dya` は現在固定中の `e5c9b6915b56801193e359dd9bad4a167ce0d1b8`、BLE管理モジュールとOLEDモジュールの既定ブランチ先端も現在の固定版と一致しています。新しいという理由だけでDYA非対応のZMKブランチへ切り替えません。

- [DYA対応ZMK](https://github.com/cormoran/zmk/tree/main%2Bdya)
- [BLE管理](https://github.com/cormoran/zmk-module-ble-management)
- [OLED](https://github.com/pukuhei/zmk-tom-oled)

## 利用者側の確認

同じ軽量版の左右UF2をそれぞれ書き込み、通常のUSB接続とBluetooth接続で入力の重さ・フリーズ再発を確認してください。直前のDYA版からは設定初期化不要です。Studioの設定が終わったら接続を閉じると、設定通信用のやり取りを減らせます。ログ採取ツールの起動は不要です。

ビルドと回帰テストの成功は、実機の長時間安定性を保証しません。
